# Vitis HLS Flow - HSL_Vitis

This folder contains the Vitis HLS project used to synthesize and verify the grayscale accelerator kernel.

## 1) Requirements

### Software
- Vitis HLS 2024.1 (or a compatible version with Vivado flow support)
- Linux shell environment (Ubuntu recommended)
- Standard C/C++ runtime tools available on the system

### Environment setup
Before running HLS, load the Xilinx tools environment:

```bash
source /tools/Xilinx/Vitis/2024.1/settings64.sh
```

If your installation is in a different path, use the corresponding `settings64.sh`.

### Input data requirement
- `input.raw` must exist in this same folder.
- Expected format: RGB888 raw image for 1920x1080.
- Expected size: 1920 x 1080 x 3 = 6,220,800 bytes.

Quick size check:

```bash
wc -c input.raw
```

## 2) How to run

From this directory (`HSL_Vitis/`):

```bash
vitis_hls -f run_hls.tcl
```

This command executes the full scripted flow defined in `run_hls.tcl`:
- C Simulation (`csim_design`)
- C Synthesis (`csynth_design`)
- C/RTL Co-simulation (`cosim_design -rtl verilog`)
- IP export (`export_design -format ip_catalog`)

## 3) Expected outputs

After a successful run:
- Project directory: `gray_kernel_prj/`
- Synthesis reports: `gray_kernel_prj/solution1/syn/report/`
- Co-simulation artifacts: `gray_kernel_prj/solution1/sim/`
- Exported IP: `gray_kernel_prj/solution1/impl/ip/`
- Tool log: `vitis_hls.log`

The executions returns the result `output.raw` in this locations:
- `gray_kernel_prj/solution1/sim/wrapc_pc/output.raw`
- `gray_kernel_prj/solution1/sim/wrapc/output.raw`
- `gray_kernel_prj/solution1/csim/build/output.raw`

## 4) Importance of files in this folder

- `run_hls.tcl`
	- Main automation script. It defines the top function, part, clock, and all flow stages.
	- Also collects the generated simulation output and copies it to `HSL_Vitis/output.raw`.
	- Most important file for reproducible runs.

- `gray_kernel.cpp`
	- HLS kernel implementation (`gray_kernel`).
	- Defines interfaces (`m_axi`, `s_axilite`) and dataflow/pipeline pragmas.

- `tb_gray.cpp`
	- C testbench for functional verification.
	- Reads `input.raw`, calls kernel, writes `output.raw`.

- `input.raw`
	- Input stimulus file used by testbench.
	- If missing or wrong size/format, simulation fails or results are invalid.

- `gray_kernel_prj/`
	- Generated project/results folder.
	- Not required before running; created/updated by Vitis HLS.

- `vitis_hls.log`
	- Execution log generated by Vitis HLS.
	- First place to inspect if something fails.

## 5) Common issues

- Part not found:
	- Edit `run_hls.tcl` and adjust `set FPGA_PART`.
	- The file already includes a commented alternate board-based value.

- Command not found (`vitis_hls`):
	- Environment not loaded. Source the correct `settings64.sh` first.

- Missing `input.raw`:
	- Place the file in `HSL_Vitis/` with the expected raw RGB content.

## 6) Minimal run checklist

1. `cd HSL_Vitis`
2. `source <your-vitis-install>/settings64.sh`
3. Verify input file exists and size is correct
4. `vitis_hls -f run_hls.tcl`
5. Review reports in `gray_kernel_prj/solution1/syn/report/`
