# Image processing system using SystemC and TLM 2.0

## Description

This project implements a Transaction-Level Model (TLM) of an image processing system in SystemC.

The architecture is composed of:

- Processor
- RAM Memory
- Persistent storage
- Image Processing Accelerator

The accelerator receives an RGB image stored in memory and generates a grayscale version of the same image

# Module Organization

## Procesor 

The processor cordinates the execution flow

It is charged of:

- Read image from storage
- Transfer image to RAM
- Configure the accelerator
- Start processing
- Store final image

## RAM

Stores:

- Input RGB image
- Output grayscale image

Provides TLM target interface

## Accelerator

Responsible for RGB to grayscale conversion

The conversion is:

Gray = 0.299*R + 0.587*G + 0.114*B

It also provides memory-mapped control registers

## Storage

Persistent memory device. It loads the image from disk and save processed image.

# Transaction Format
The system uses TLM-2.0 Generic Payloads transactions

## Write Transaction

| Field    | Description       |
| -------- | ----------------- |
| Command  | TLM_WRITE_COMMAND |
| Address  | Target address    |
| Data Ptr | Source buffer     |
| Length   | Number of bytes   |

## Read Transaction

| Field    | Description        |
| -------- | ------------------ |
| Command  | TLM_READ_COMMAND   |
| Address  | Target address     |
| Data Ptr | Destination buffer |
| Length   | Number of bytes    |


# Memory Map

| Address Range | Module      |
| ------------- | ----------- |
| 0x00000000    | RAM         |
| 0x10000000    | Storage     |
| 0x20000000    | Accelerator |

## Accelerator Registers

| Address    | Register    |
| ---------- | ----------- |
| 0x20000000 | START       |
| 0x20000004 | STATUS      |
| 0x20000008 | INPUT_ADDR  |
| 0x2000000C | OUTPUT_ADDR |

# GEM5 Virtual Prototype (Evaluation 2)

The project also includes a GEM5-based virtual prototype where an ARM64 CPU configures and triggers the image accelerator through memory-mapped registers.

## Location

- `GEM5/`

## Requirements

- GEM5 compiled for ARM (`build/ARM/gem5.opt`)
- ARM64 cross compiler (`aarch64-linux-gnu-gcc`)
- Python3 and SCons

## Quick start

From repository root:

```bash
cd GEM5
chmod +x scripts/build.sh
./scripts/build.sh
```

This script automates:

- Accelerator file integration in GEM5
- GEM5 build/update
- ARM64 driver compilation
- Simulation run
- Output verification

## Manual run

```bash
~/gem5/build/ARM/gem5.opt \
    --outdir=GEM5/gem5_output \
    GEM5/scripts/run_gem5.py
```

## Main files

- `GEM5/scripts/build.sh`: end-to-end automation
- `GEM5/scripts/run_gem5.py`: virtual platform configuration
- `GEM5/src/image_accelerator_gem5.hh` and `GEM5/src/image_accelerator_gem5.cc`: GEM5 wrapper
- `GEM5/driver/accelerator_driver.c`: ARM64 user-space test program

For full technical details, see: `GEM5/README.gem5.md`


# Vitis HLS Flow (HSL_Vitis)

The repository includes the HLS implementation and verification flow for the grayscale accelerator kernel.

## Location

- `HSL_Vitis/`

## Requirements

- Vitis HLS 2024.1 (or compatible)
- Linux shell environment
- `input.raw` in `HSL_Vitis/` (RGB888, 1920x1080)

## Environment setup

```bash
source /tools/Xilinx/Vitis/2024.1/settings64.sh
```

## Run HLS flow

From repository root:

```bash
cd HSL_Vitis
vitis_hls -f run_hls.tcl
```

The TCL flow runs:

- C simulation
- C synthesis
- C/RTL co-simulation (Verilog)
- IP export

## Expected outputs

- `HSL_Vitis/gray_kernel_prj/solution1/syn/report/`: synthesis reports
- `HSL_Vitis/gray_kernel_prj/solution1/sim/`: co-simulation artifacts
- `HSL_Vitis/gray_kernel_prj/solution1/impl/ip/`: exported IP
- `HSL_Vitis/output.raw`: generated grayscale output

For complete instructions and troubleshooting, see: `HSL_Vitis/README.md`
